# Expo migration: master plan for agents

This is the master plan for moving **TrainingPlan** from bare React Native 0.68 to **Expo SDK 57** and a current library stack. Several agents do the work in parallel, each in its own git worktree. Every agent reads this file first and then its own brief in `agents/`.

> Status: planning. Decisions D1–D6 below must be answered by Dmytro before Phase 1 starts.

---

## 1. Where we are and where we're going

| Area | Now | Target |
|---|---|---|
| Runtime | React Native 0.68.1, React 17, legacy architecture | **Expo SDK 57**: RN 0.86, React 19.2, New Architecture (required), Hermes v1 |
| Native projects | `android/` and `ios/` committed by hand | Generated by Expo (CNG). `android/` and `ios/` are gitignored. Native config goes in `app.config.ts` and config plugins |
| Builds | Gradle scripts (`bandle:release`) | EAS Build profiles: `development`, `preview`, `production` |
| Language | TypeScript (version unpinned, no tsconfig in the app) | TypeScript as shipped by SDK 57, `tsconfig.json` extending `expo/tsconfig.base` |
| Navigation | React Navigation 6 (stack, native-stack, bottom-tabs) | React Navigation 7. Expo Router is deferred (see D4) |
| State | RTK 1.8, react-redux 7, redux-persist 6 | RTK 2, react-redux 9, redux-persist 6 on AsyncStorage |
| Backend | Firebase JS 8.2.2, namespaced API | Latest Firebase JS SDK, modular API, auth persisted with `getReactNativePersistence(AsyncStorage)` |
| Google auth | `@react-native-google-signin/google-signin` v8 | Latest version, using its Expo config plugin |
| Sound | react-native-sound, mp3s in `android/res/raw` | `expo-audio`, mp3s in `app/Assets/sounds` |
| Text-to-speech | react-native-tts | `expo-speech` |
| Keep screen awake | react-native-keep-awake | `expo-keep-awake` |
| Background workout | react-native-background-actions (Android foreground service) | Timer based on timestamps, plus `expo-notifications` for cues (see D3) |
| Animation and gestures | Reanimated 2.8, gesture-handler 2.1 | Reanimated 4 + `react-native-worklets`, gesture-handler as installed by Expo |
| Icons | react-native-vector-icons 9 | `@react-native-vector-icons/material-design-icons` (`@expo/vector-icons` was deprecated in SDK 56) |
| Config and secrets | `app/Utils/constants.local.ts` (gitignored) | `EXPO_PUBLIC_*` env vars in `.env` (gitignored), `.env.example` committed |
| Tests and lint | Jest 26, one placeholder test, Prettier | `jest-expo` + React Native Testing Library, `eslint-config-expo`, Prettier, Maestro E2E flows |
| Admin panel | CRA 5, React 18, MUI 5, Firebase 8 | Vite, React 19, MUI current, latest Firebase modular, React Router current (optional, D5) |

Rule for versions: **always install native-facing packages with `npx expo install <pkg>`** so the SDK picks compatible versions. For JS-only packages, use the current major and write the version you chose in your handoff.

## 4. Branches and worktrees

- Integration branch: **`migration/expo`**, created from `main` (D6).
- Each Phase 1 agent creates its branch from `migration/expo` **after A0 has merged**:

```bash
git fetch origin
git worktree add ../tp-a1-data      -b migration/a1-data      migration/expo
git worktree add ../tp-a2-auth      -b migration/a2-auth      migration/expo
git worktree add ../tp-a3-media     -b migration/a3-media     migration/expo
git worktree add ../tp-a4-playback  -b migration/a4-playback  migration/expo
git worktree add ../tp-a5-ui        -b migration/a5-ui        migration/expo
git worktree add ../tp-a6-admin     -b migration/a6-admin     migration/expo
git worktree add ../tp-a7-quality   -b migration/a7-quality   migration/expo
```

- Each worktree runs `npm install` on its own. Never share `node_modules` between worktrees.
- Make small, focused commits. Rebase on `migration/expo` before handing off. Never force-push `migration/expo`.

## 5. Who owns which files

To keep merges painless, every path belongs to exactly one Phase 1 agent. If you need to change a file you don't own, make the smallest possible edit and list it under **"Touched outside ownership"** in your handoff.

| Path | Owner |
|---|---|
| `app/Utils/firebase.ts`, `app/store/**`, `app/Hooks/redux.ts` | A1 |
| `app.config.ts`, `eas.json`, `.env.example`, `app/services/googleAuth.ts`, `app/Screens/LoginScreen/AppGoogleSignInButton.tsx` | A2 |
| `app/services/audio.ts`, `app/services/speech.ts`, `app/services/keepAwake.ts`, `app/Hooks/useTTS.tsx`, `app/Hooks/AppHelperProvider.tsx`, `app/Components/AppSoundPicker/**`, `app/Screens/SettingsScreen/**`, `app/Assets/sounds/**` | A3 |

| `admin/**` | A6 |
| `__tests__/**`, `e2e/**`, `jest.config.js`, `eslint.config.js`, `.prettierrc.js`, `docs/migration/TESTING.md` | A7 |
| `docs/migration/STATUS.md`, `docs/migration/DECISIONS.md`, merge commits on `migration/expo` | A8 |

Shared files have extra rules:

- **`package.json` and `package-lock.json`**: add or remove dependencies only through `npx expo install` or `npm`. Never edit by hand. On a lock conflict, A8 takes one side and runs `npm install` again; it never merges the lock file by hand.
- **`app.config.ts`**: A0 declares every expected plugin up front. Other agents only change their own plugin's options. If you need a new plugin or permission, ask A2 in your handoff, or add it in one clearly commented block.
- **`app/Utils/constants.ts`**: append only.
- **Formatting**: nobody reformats files they otherwise wouldn't touch. A8 runs one repo-wide Prettier/ESLint `--fix` pass as the **last** commit of Phase 2.

## 6. Seams created by A0

A0 sets up thin service modules so Phase 1 agents can swap implementations without touching each other's callers. **Keep these signatures stable.** If one has to change, note it in your handoff and update every caller in the same commit.

```ts
// app/services/audio.ts             (A3)
export type SoundPlayer = { play(): void; stop(): void; release(): void }
export function createSoundPlayer(type: SoundType): SoundPlayer
export function previewSound(type: SoundType): void
export function configureAudioSession(opts: { duckOthers: boolean }): Promise<void>

// app/services/speech.ts            (A3)
export function speak(text: string, opts?: { rate?: number; pitch?: number; volume?: number }): void
export function stopSpeaking(): void
export function setSpeechDefaults(opts: { rate?: number; pitch?: number; duck?: boolean }): void

// app/services/keepAwake.ts         (A3)
export function activateKeepAwake(tag?: string): void
export function deactivateKeepAwake(tag?: string): void

// app/services/backgroundSession.ts (A4)
export type SessionInfo = { title: string; description: string; color?: string; progress?: { value: number; max: number }; endsAt?: number | null }
export function startSession(info: SessionInfo): Promise<void>   // Android ongoing notification; no-op on iOS
export function updateSession(info: Partial<SessionInfo>): Promise<void>
export function stopSession(): Promise<void>
// Added by A4 (additive):
export type CueNotification = { id: string; at: number; title: string; body: string }
export function scheduleCues(cues: CueNotification[], opts?: { sound?: SoundType; vibrate?: boolean; color?: string }): Promise<void>
export function cancelCues(): Promise<void>
export function requestNotificationPermission(): Promise<boolean>

// app/services/googleAuth.ts        (A2)
export function configureGoogleSignIn(): void
export function getGoogleIdToken(): Promise<string>     // throws on cancel/failure
export function signOutGoogle(): Promise<void>

// app/Common/Icon/Icon.tsx          (A5)
export function Icon(props: { name: string; size?: number; color?: string; style?: StyleProp<TextStyle> }): JSX.Element
```

Firebase: A0 moves the app to the latest `firebase` package using the **`firebase/compat/*` imports**. These keep the v8 namespaced API, so the app boots with no data-layer changes, and A1 then converts to the modular API.

## 7. Rules for every agent

1. Read `README.md`, your brief, and `DECISIONS.md` before changing anything.
2. Stay within the files you own (§5). Don't upgrade packages that belong to another agent.
3. Native packages: `npx expo install`. Then run `npx expo-doctor` and fix what it reports for your packages.
4. Before handing off, all of these must pass in your worktree:
   - `npx tsc --noEmit`
   - `npx expo lint` (once A7 has added the config; until then, don't introduce new warnings)
   - `npm test`
   - The app boots in a **development build** (`npx expo run:android` / `run:ios`, or an EAS dev build) and you've manually tested the flows your brief lists.
5. Don't commit secrets. Firebase config comes from `EXPO_PUBLIC_*` env vars. `google-services.json` and `GoogleService-Info.plist` are only committed if D2 requires them (with the JS SDK they aren't needed).
6. End commit messages with the attribution lines the repo or session requires.
7. Hand off by filling in `docs/migration/handoff/<agent-id>.md` from `handoff/TEMPLATE.md`, then opening a PR or telling A8 your branch is ready.

## 8. When the migration is done

- [ ] The app builds with EAS (`preview` profile) for Android and iOS from a clean clone.
- [ ] No `android/` or `ios/` folders in git. `npx expo prebuild --clean` reproduces them.
- [ ] None of these remain in `package.json`: `react-native-sound`, `react-native-tts`, `react-native-keep-awake`, `react-native-background-actions`, `react-native-vector-icons`, `firebase@8`, `react-native-web@0.17`, `redux-typescript`, or stale `@types/*` for removed libraries.
- [ ] `npx expo-doctor` reports no issues.
- [ ] Every flow in `docs/migration/TESTING.md` passes on a real Android device and an iOS device or simulator.
- [ ] Data saved before the migration (redux-persist state, Firebase user data) still loads after updating.
- [ ] `ReadMe.md` explains how to set up, run, and build the new stack.
