# Handoff — A1 / Data and Firebase

**Branch:** migration/a1-data  **Last commit:** see `git log` (this handoff commit follows 0906ac4)  **Date:** 2026-10-11

## Done
- **Firebase init** (`app/Utils/firebase.ts`) uses the modular SDK:
  - `initializeApp(config)`, with config from `EXPO_PUBLIC_FIREBASE_*`. A dev warning is shown when the vars are missing.
  - `initializeAuth(app, { persistence: getReactNativePersistence(AsyncStorage) })`.
  - `initializeFirestore(app, { experimentalAutoDetectLongPolling: true })`.
  - `getDatabase(app)`.
  - All of these are guarded with `getApps()` and fall back to `getAuth`/`getFirestore` on Fast Refresh.
- **Compat removed.** `grep -r "firebase/compat\|from 'firebase'" app` returns nothing.
- **Storage and Functions removed.** Confirmed unused: `FB_Store` had no callers and nothing used `firebase/functions`. Nothing in `app/` uploads files. `StoredFile.downloadUrl` values come pre-made from the Realtime DB.
- **All thunks converted** (Plans, Workout, Publications, User) to `doc/getDoc/getDocs/query/where/orderBy/startAt/endAt/limit/setDoc/updateDoc/deleteDoc/arrayUnion/arrayRemove/writeBatch`. The Realtime DB `ExerciseImages` read uses `get(ref(rtdb, …))`.
  - **Firestore document shapes are unchanged.** A test asserts the exact field set for publications.
  - `serverTimestamp`/`increment`/`onSnapshot`/`runTransaction` were not needed, because the old code didn't use them. `lastUpdated` stays a client epoch-ms number, as the admin panel and pagination expect.
- **Offline sync logic** moved into the pure `app/store/sync.ts`, with the same rules as before. `app/store/firestore.ts` `pushSync()` writes the result in a `writeBatch` (chunks of 450 writes).
  - As before, these writes are not awaited, so the list loads at once. Failures are now logged instead of becoming unhandled rejections.
  - New guard: `ownedBy()` keeps cached items that belong to another uid out of a user's sync.
- **Publications query** building moved into the pure `publicationsQuery.ts`, with the same query shapes and the same `startAt`/`endAt` pagination on `lastUpdated`.
- **Auth** (`UserAC.ts`):
  - Email sign-up, sign-in and sign-out use the modular functions.
  - Google sign-in: `getGoogleIdToken()` (A2's seam), then `signInWithCredential(auth, GoogleAuthProvider.credential(idToken))`.
  - Sign-out calls `signOutGoogle()` first. Its failure is logged and no longer stops the Firebase sign-out.
- **`onAuthStateChanged`** (`UserReducer/authListener.ts` + pure `authState.ts`) starts in the `persistStore` callback, so it compares against the rehydrated user:
  - Firebase user, but no or another Redux user: set the user, and request user data unless a sign-in thunk is already running.
  - Same uid with changed profile fields: update.
  - No Firebase user while Redux has one: `sessionEnded`. This clears the user so the login screen shows. Cached workouts and plans are kept, so unsynced offline edits survive a re-login.
- **Redux:**
  - `extraReducers` were already builder callbacks (A0). `configureStore` middleware uses the callback form, with the serializable check **enabled** and the redux-persist actions ignored. `immutableCheck` ignores the large `workoutReducer.exerciseImages`.
  - `app/Hooks/redux.ts` uses `useDispatch.withTypes<AppDispatch>()` / `useSelector.withTypes<RootState>()`. The exported hook names are unchanged.
  - The `LogBox` ignore for the Firebase 8 AsyncStorage warning was removed (the warning came from Firebase 8).
- **Thunks no longer mutate their arguments** (`props.lastUpdated = …`). They build new objects. The old way throws on frozen (state-derived) arguments.
- **Bugs fixed in owned files:**
  1. `WorkoutSlice` cleared `deletedWorkoutUids` when the list loaded **offline** (`!isInternet`). Pending offline deletes were lost. It now clears them when online, like `PlansSlice`.
  2. `publicationsAC.save` returns `null` when the user already downloaded the publication. The reducer destructured `null` and threw. It also overwrote `userPublications` with `publications`.
  3. `updatePlan` / `updateWorkout` reducers crashed when nothing was selected (`state.selectedPlan.uid` on `null`).
  4. Publications pagination stopped after the second page: `isPublicationsAll = old.length <= new.length` was always true. It is now true only when a next chunk adds nothing new.
  5. `signInWithGoogle.pending` now sets `isLoading`. `authListener` relies on this.
- **Tests:** 9 suites, 69 tests under `app/store/**/__tests__/`:
  - every slice;
  - plan, workout, publication and user thunks with Firebase mocked (save/load/sync paths);
  - the pure helpers;
  - a persist test that rehydrates state in the format the old app wrote.

### Persist versioning
- **Unchanged on purpose.** `key: 'root'`, no `version` (it stays at the default -1), no whitelist or blacklist, so the whole state is persisted.
- Stored state from the old app rehydrates as-is (covered by `persist.test.ts`). No `migrate` step was needed, because no slice shape changed.

### Long-polling decision
`experimentalAutoDetectLongPolling: true` (the SDK default since v10) replaces the old `experimentalForceLongPolling: true`. If Firestore requests hang on a device (spinner never ends, `getPlans`/`getWorkouts` never settle), switch to `experimentalForceLongPolling: true` in `createFirestore()` and write down which device and network showed it.

## Known issues / follow-ups
- Background sync writes (`pushSync`, `deleteWorkouts`, `likeToggle`) are not awaited, the same as the old code, so a server-side rejection only shows as a `console.warn`.
- `getPlans` and `getWorkouts` still load at most `QUERY_LIMIT` (30) docs per user, as before. Users with more than 30 workouts only see the first 30 remote ones plus their cached ones.
- The listener's "login" path can run `dataRequest` a second time during Google sign-in. This is harmless (an idempotent read).
- The thunk payload and slice typing is still the loose pre-migration style (`addCase(x.type, …)` with `PayloadAction` casts). It could move to `createAsyncThunk.withTypes<{ state: RootState; rejectValue: string }>()` later.
