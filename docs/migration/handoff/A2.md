# Handoff: A2, auth, native config and EAS

**Branch:** migration/a2-auth  **Last commit:** see `git log` (this handoff follows e6a23ef)  **Date:** 2026-10-11

## Done
- **Google Sign-In** (`@react-native-google-signin/google-signin` 16.1.5, "original" API, no Firebase config files, per D2):
  - `app/services/googleAuth.ts` implements the seam from README §6.
    - `configureGoogleSignIn()` can be called more than once. It reads `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` and, on iOS, `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`. If one is missing it logs a warning and turns Google sign-in off, rather than crashing the iOS SDK.
    - `getGoogleIdToken()` runs `ensureConfigured`, then `hasPlayServices({ showPlayServicesUpdateDialog: true })` on Android, then `signIn()`. It maps `{ type: 'cancelled' }` and the native error codes to a typed `GoogleAuthError` with one of these codes: `cancelled | in_progress | play_services_unavailable | not_configured | no_id_token | developer_error | unknown`.
    - `signOutGoogle()` never throws. It does nothing when there is no Google session, which is the case for email users. If there is one, it calls `revokeAccess()` and then `signOut()`.
  - The pure logic is in `app/services/googleAuthCore.ts`, with 14 unit tests in `app/services/__tests__/googleAuthCore.test.ts`. They pass under a throwaway Jest 29. The file starts with `// @ts-nocheck` until A7 adds Jest types.
  - Dropped `offlineAccess` and `forceCodeForRefreshToken`. Only the ID token is used, and `forceCodeForRefreshToken` made Android show the consent screen on every sign-in.
  - `AppGoogleSignInButton.tsx` uses the library's `GoogleSigninButton` again, with the same size, colour and style as before the migration.
- **`app.config.ts`**
  - `APP_VARIANT` can be `development`, `preview` or `production` (the default). The variant sets the name suffix, the `.dev` / `.preview` ID suffix and the scheme (`trainingplan`, `trainingplan-dev`, `trainingplan-preview`). An unknown value throws.
  - `version` comes from `package.json`. EAS manages `versionCode` and `buildNumber`.
  - Added the permissions and `blockedPermissions` listed below.
  - The google-signin plugin is added with `iosUrlScheme`, derived from the iOS client ID. Without that env var it is left out: a local build only warns, an EAS iOS build fails.
  - Added the `expo-dev-client` plugin.
  - `expo-build-properties` stays on the SDK defaults, on purpose.
  - `extra.eas.projectId` is set from `EAS_PROJECT_ID`.
- **`eas.json`** has the profiles `development` (dev client, internal, APK), `development-simulator`, `preview` (internal APK) and `production` (store AAB, `autoIncrement`). Each one is bound to its EAS `environment` and `APP_VARIANT`, with `appVersionSource: remote`. I checked it with `@expo/eas-json` from eas-cli 24.12.1. `eas build` itself needs a login and network, so I couldn't run it.
- **`.env.example`** lists every key. `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` replaces `EXPO_PUBLIC_GOOGLE_IOS_URL_SCHEME`, because the scheme is now derived from the client ID. It also documents `APP_VARIANT` and `EAS_PROJECT_ID`.
- **`docs/migration/BUILD.md`** (new) covers the variants, EAS env vars, first-time EAS setup, Android keystore handling and the Firebase/Google console checklist.
- No references to `google-services.json` or `GoogleService-Info.plist` are left in code or config.

## Firebase / Google console checklist (Dmytro)
Full steps are in [BUILD.md §4–5](../BUILD.md). In short:
1. Firebase → Authentication → Google provider enabled → copy the **Web client ID** into `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`.
2. Android apps for `com.trainingplantogether_cli`, `.dev` and `.preview`. Add **SHA-1 and SHA-256** of:
   - production: the Play App Signing key, the EAS upload key, and the old debug key while it is still in use;
   - dev and preview: their EAS keystores;
   - local debug builds: `~/.android/debug.keystore`.
3. iOS apps for `com.trainingplantogether-cli`, `.dev` and `.preview` (bundle ID pending D1). Put each iOS OAuth client ID into the matching EAS environment.
4. Check that the OAuth consent screen is published.
5. **Keystore:** old release builds were signed with the **public React Native debug keystore** (SHA-1 `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25`). Do not let EAS generate a new production keystore if the app is published. Import the old one, or reset the upload key through Play App Signing (BUILD.md §4).
6. Before the first production build, set the remote Android `versionCode` above the last Play upload: `eas build:version:set -p android`.

## Requests to other agents
- **A1:** in `UserAC.signInWithGoogle`, handle `isGoogleSignInCancelled(e)` (exported from `app/services/googleAuth`) as "no error". For example, return `thunkAPI.rejectWithValue('')` or use a separate path, so the error toast isn't shown. **Without this, the acceptance criterion "cancel shows no error toast" fails**: the cancel currently rejects with the message "Google sign-in was cancelled". Every other `GoogleAuthError` message is readable by users and can go to the toast as it is. Also, `signOutGoogle()` no longer throws, so `signOut` can't fail because of Google.
- **A3:** decide on `enableBackgroundPlayback` for expo-audio. It controls `FOREGROUND_SERVICE_MEDIA_PLAYBACK` on Android and `UIBackgroundModes: [audio]` on iOS. If cues have to play while the screen is locked during a workout, keep it and tell A2/A8. Otherwise set it to `false`.
- **A4:** `POST_NOTIFICATIONS` has been added. Tell A2/A8 if you need anything else, such as exact alarms (`SCHEDULE_EXACT_ALARM`) or a notification icon/colour in the expo-notifications plugin options.
- **A7:** remove `// @ts-nocheck` from `app/services/__tests__/googleAuthCore.test.ts` once Jest types are installed. The test doesn't import the native library: at import time, `google-signin` calls `TurboModuleRegistry.getEnforcing`, so any test that renders `AppGoogleSignInButton` needs `jest.mock('@react-native-google-signin/google-signin')` (the package ships `jest/setup`).
- **A8:** `npx expo-doctor` still can't run the config-schema check here. Run it once with network access.

## Known issues / follow-ups
- **D1 is still open.** The iOS bundle ID is `com.trainingplantogether-cli` because `_` is illegal on Apple. Changing it later means re-registering the iOS app in Firebase/Google and EAS. The app was never on the App Store, so there's no store impact.
- **Duplicated helper.** The Expo config loader can't import other TypeScript files, so `iosUrlSchemeFromClientId` exists twice: in `app.config.ts` and in `googleAuthCore.ts` (where it is tested). Keep them in sync.
- **Expo Go.** google-signin needs native code, so the app no longer opens in Expo Go. Use the dev client (`development` profile).
- **Old debug keystore.** The public React Native debug keystore and the old `google-services.json` are still in git history at `ee75ad7`. Neither is a secret: the keystore is public, and the Firebase web config ends up in the bundle anyway.
