# Handoff — A5 / UI libraries and navigation

**Branch:** migration/a5-ui  **Last commit:** see `git log` (the handoff commit follows ea7c052)  **Date:** 2026-10-11

## Done
- **React Navigation 7** (`app/routers/**`, `app/utils/types.ts`)
  - One param list per navigator: `AuthStackParamList`, `AppTabParamList`, `PlansStackParamList`, `WorkoutsStackParamList`, `PublicationsStackParamList`, `ProfileStackParamList` (plus the shared fragments `PlayableStackParamList` and `PublicationScreensParamList`). Screens use navigator-specific navigation types (`AuthNavigation`, `PlansNavigation`, `WorkoutsNavigation`, `PlayableNavigation`, `PublicationsNavigation`, `ProfileNavigation`), so `tsc` catches a `navigate()` to a screen that isn't in the current stack or that has the wrong params.
  - Navigators are created once at module level. Before, every router called `createStackNavigator()` inside its render function, which made a new navigator component on each render and remounted the stack.
  - Each navigator has an explicit `id` (`AuthStack`, `AppTabs`, `PlansStack`, `WorkoutsStack`, `PublicationsStack`, `ProfileStack`). The Navigation 7 types only accept a missing `id` under `strictNullChecks`, and `tsconfig.json` has `strict: false`.
  - Bottom tabs: `sceneContainerStyle` changed to `screenOptions.sceneStyle`, so the tab scene background colour is applied again.
  - `navigate` behaviour change: Registration → "Log in" now uses `popTo(Login)`. In Navigation 7, `navigate` no longer goes back to an existing screen; it would push a second Login. No other `navigate` call targets a screen lower in the stack or in another navigator.
  - **Behaviour fix:** the Profile stack now also registers `PublicationPlan` and `PublicationWorkout`. `components/publication` is rendered on the Profile screen (your own publications), and tapping one used to navigate to screens that only existed in the Publications stack, so nothing happened. Now they open inside the Profile tab.
  - Tab route names moved to a `TabName` enum (appended to `app/utils/constants.ts`), with the same string values as before.
  - `NavigationContainer` gets a theme built from the app palette (`app/theme/navigation-theme.ts`), so stack cards, the background behind transitions, and default header/tab colours match light and dark mode. Stack screens also set `cardStyle.backgroundColor`.
  - `GoBackSubmitModal`: the `beforeRemove` listener is typed by hand (with `strict: false`, the inferred event type loses `preventDefault`). It also no longer shows a second "Are you sure" alert after you confirm. Before, `onConfirm` → `goBack()` hit the still-mounted listener again.
- **Navigator choice: all stacks stay on `@react-navigation/stack` (JS stack); `@react-navigation/native-stack` was removed.** The app's look depends on a compact 40dp header with a custom shadow (`useScreenOptions`), and the in-screen `AppHeader` overlay is positioned at exactly `top: -40` over that header (selection/edit toolbars in MyPlans, Workouts and Workout). Native-stack headers don't support a custom height or shadow, so switching would change the look and break the overlay.
- **Reanimated 4 + worklets.** The app code uses no Reanimated APIs directly. `babel-preset-expo` adds the worklets plugin itself (A0), so `babel.config.js` needs nothing more. I checked `react-native-draggable-flatlist` 4.0.3 against Reanimated 4.5: everything it imports still exists (`useSharedValue`, `useAnimatedReaction`, `useAnimatedScrollHandler`, `withSpring`, `runOnJS`, …). It doesn't use the removed `useAnimatedGestureHandler` or `useWorkletCallback`. The root is wrapped in `GestureHandlerRootView` (already there). The legacy `import 'react-native-gesture-handler'` side-effect imports were dropped, since RNGH 2 doesn't need them.
- **Icons:** the `Icon` seam now uses `@react-native-vector-icons/material-design-icons` through its `static` entry. The font is embedded at build time: the package's config plugin adds `MaterialDesignIcons.ttf` to `UIAppFonts` on iOS (verified in the prebuild `Info.plist`), and its autolinked Android module ships the font. No runtime font loading, so no flash of missing icons. `app/theme/icons.ts` is `as const satisfies Record<string, IconName>`, so `tsc` rejects unknown names. The literal names in `AppRouter` and `ButtonCounter` moved into `icons.ts`.
  - **Renamed icons: none.** All 34 names in use exist in the new set (checked against the glyph map, and covered by a unit test).
- **Third-party UI**
  - `react-native-draggable-flatlist`: kept, behind the new `app/common/draggable-list/draggable-list.tsx` seam (`DraggableScrollContainer`, `DraggableList`, `DraggableItem`, `DraggableRenderItemParams`). The three screens use only the seam, so a swap to `react-native-reorderable-list` touches one file if the device test fails.
  - `react-native-scroll-picker-wheel`: **replaced** by a FlatList snap picker in `common/swipe-selector` with the same props (`onChange`, `value`, `step`, `maxValue`). The library was unmaintained, depended on the undeclared `prop-types`, and ignored the colour props passed to it. Index math is in `pickerMath.ts`, with tests.
  - `react-native-keyboard-aware-scroll-view`: **replaced** by `react-native-keyboard-controller`'s `KeyboardAwareScrollView` (Login, Registration), with `KeyboardProvider` at the root. The old library is a no-op on Android by default and relied on `adjustResize`, which doesn't resize under edge-to-edge. It also used `findNodeHandle`/`UIManager` APIs. The scroll view is now the screen's scroller (it used to be nested inside `Page`'s ScrollView, so it had nothing to scroll).
  - `react-native-circular-progress`: removed (never imported).
  - `react-native-countdown-circle-timer` 3.2.1 (PlayingScreen, A4): pure JS on `react-native-svg`. It compiles and bundles; no change.
  - `@react-native-community/slider` 5.2.0 (SettingsItem, A3): compiles; see Requests.
  - `react-native-svg` icons in `app/assets/icons/*.tsx`: compile and bundle unchanged.
- **Edge-to-edge**
  - New `app/theme/insets.ts` → `useAppInsets()` (safe-area insets plus `header`/`footer` heights), and the pure `getBarHeights()` in `barHeights.ts`.
  - Stack header height = 40 + top inset. React Navigation draws the header behind the status bar, so the old fixed `height: 40` would have squashed the header under the status bar.
  - Tab bar: height and bottom padding grow by the bottom inset. `Page` bottom padding, `AppFooter`, `AddMoreButton`, WorkoutScreen's list height and WorkoutsScreen's list padding use the inset-aware footer. The Toaster sits below the status bar or notch.
  - The deprecated RN `SafeAreaView` was replaced by `View` in `Page` and `Loading` (the header and tab bar handle the insets).
  - `SafeAreaProvider` is at the root.
- **React 19:** no `forwardRef` or ref-as-prop issues in A5 files. `SwitchLib` keeps `static defaultProps`, which React 19 still supports on class components.
- **Theme:** the status bar style (`expo-status-bar`), the root view background (`expo-system-ui` `setBackgroundColorAsync`), the `GestureHandlerRootView` background (was a hard-coded `seashell`) and the navigation theme all follow the palette selected in Settings. The app theme is the user's choice, not the system scheme. The Android navigation bar uses the OS default contrast scrim (`expo-navigation-bar` not added; see Known issues).
- **Types:** `Parents.tsx` style props are now `StyleProp<ViewStyle>` for containers and `StyleProp<TextStyle>` for texts. `useScreenOptions()` returns `StackNavigationOptions`. With those fixes, `app/env.d.ts` references all of `expo/types` (TODO(A5) resolved).
- **Every `TODO(A5)` and `@ts-expect-error` is gone** (7 markers + Icon + env.d.ts).
- Unit tests (run once A7's jest config is in): `app/theme/__tests__/{navigationTheme,barHeights,icons}.test.ts`, `app/common/swipe-selector/__tests__/picker-math.test.ts`. They declare the jest globals locally (module scope) so `tsc` passes without `@types/jest`; A7 can delete those 3–4 `declare const` lines once jest types are installed. I checked the `pickerMath` tests with a minimal runner (4/4 pass) and the icon names against the glyph map (34/34).

## Known issues / follow-ups
- **Android navigation bar buttons** (3-button mode) rely on the OS contrast scrim (`expo-navigation-bar` is not installed; its default `enforceContrast: true`). If the scrim over the tab bar looks wrong on a device, add `expo-navigation-bar` with `enforceContrast: false` and set `NavigationBar.setStyle(isDark ? 'dark' : 'light')` in `ThemedRoot` (`app/app.tsx`). That needs a plugin entry in `app.config.ts` (A2).
- `react-native-draggable-flatlist` calls the deprecated `findNodeHandle` (still works under the New Architecture). Its last release is 4.0.3. Swap point: `common/draggable-list`.
- `LayoutAnimation` (used by `NotificationHandler` when toasts close) is only partly supported under the New Architecture on Android. Worst case, toasts close without animation.
- `AppModal` passes `onTouchStart={onClose}` to RN `Modal`, which ignores it. This is unchanged from before; noted only so nobody treats it as a regression.
- `tsconfig.json` has `strict: false`. React Navigation 7's types assume strict mode, which is why the navigators need explicit `id`s and the hand-typed `beforeRemove` event. Turning on `strictNullChecks` later would let both workarounds go, but it touches every agent's files.
- `appScreen.vh` (`Dimensions.get('window').height`) now includes the system bars on edge-to-edge Android. The modal heights that use `vh - …` (ImageSelector, AppColorPicker, ShareModal, CopyWorkoutsModal) may be slightly taller than before. Check them on the device (item 5).
