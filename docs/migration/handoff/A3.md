### Rate and pitch mapping
Settings stores react-native-tts units: rate on a 0.1–0.9 slider (default 0.5), pitch on a 0.5–2.0 slider (default 1.5).

| | react-native-tts (old) | expo-speech (new) | Mapping |
|---|---|---|---|
| Rate, iOS | `AVSpeechUtterance.rate = r` (the default speech rate is 0.5) | `utterance.rate = rate × AVSpeechUtteranceDefaultSpeechRate (0.5)` | **expoRate = 2 × r** |
| Rate, Android | `setDefaultRate(r)` called `setSpeechRate(r × 2)` | `setSpeechRate(rate)` | **expoRate = 2 × r** |
| Pitch, both | `pitchMultiplier = p` / `setPitch(p)` | the same | **expoPitch = p**, clamped to 0.5–2 |
| Volume | Android `KEY_PARAM_VOLUME`; ignored on iOS | `volume` 0–1 on both platforms | the same value (iOS now respects the volume slider too) |

So the old default 0.5 becomes 1.0 (normal speed), and the slider range becomes 0.2–1.8. The input is clamped to 0.05–1 before doubling.

### Audio session (`buildAudioMode`)
| Option | Value | Why |
|---|---|---|
| `playsInSilentMode` | `true` | Cues must be heard with the iOS silent switch on. This was the old `'Playback'` category. iOS also forbids `duckOthers` without it |
| `interruptionMode` | `'duckOthers'` if Settings → "Lowering other apps output level" is on, otherwise `'mixWithOthers'` | The old code mixed (`setCategory('Playback', true)`) and used `Tts.setDucking` |
| `shouldPlayInBackground` | `false` | D3: while the app is in the background, cues come from expo-notifications (A4). JS timers don't run there anyway |
| `allowsRecording`, `shouldRouteThroughEarpiece` | `false` | Not used |

Players are created with `keepAudioSessionActive: false`. iOS then deactivates the session with `notifyOthersOnDeactivation` when nothing is playing, and Android gives up audio focus when no player is playing, so music comes back up after each cue.

### Ducking (why there is a silent clip)
expo-speech has no ducking switch. On Android its TextToSpeech engine never requests audio focus, so the expo-audio session mode has no effect on speech. `beginDucking()` plays the silent clip through expo-audio for the length of each utterance:
- Android: expo-audio requests `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`. This is the same request react-native-tts made in `setDucking(true)`.
- iOS: expo-audio activates the `.playback + .duckOthers` session.

On `onDone`, `onStopped` or `onError`, the player is removed (not just paused), so focus and the session are released and expo-audio's Android "resume on foreground" logic can never restart it. The clip ends by itself after 20 s as a safety net. When ducking is off, `beginDucking()` does nothing. Cue sounds follow the same session mode, so they duck too when ducking is on.

## Known issues / follow-ups
- The ducking approach (a silent player holding focus) is device-dependent and is the part most worth checking on real hardware, especially Android OEM builds with unusual focus handling. If it misbehaves, the fallback is to drop `beginDucking()` from `speech.ts` and rely on the session mode only. That still ducks for cue sounds, and for speech on iOS, but not for speech on Android.
- The sound volume is fixed when the playing screen opens, as before (the old code also called `setVolume` once). Changes in Settings apply the next time the playing screen opens.
- The voice lookup is asynchronous. The very first phrase after app start may use the system default voice before the best English voice is known.
- An utterance longer than 20 s stops ducking when the silent clip ends. Exercise names are far shorter.
